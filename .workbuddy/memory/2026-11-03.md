## 本机构建注意事项
- 沙箱里跑 `cargo check` / `cargo build` 会失败：`build.rs` 里的 `winres` 要用 `reg.exe` 查 Windows SDK 路径，而 reg.exe 在程序黑名单里，**无法绕过**。报错特征：`Error: Os { code: 3, kind: NotFound }` + `Selected RC path: 'bin\x64\rc.exe'`。
- 因此编译验证只能靠：① IDE 的 rust-analyzer 自己跑 cargo check（`target/flycheck0/stderr` 会刷新）；② `rustfmt --emit stdout src/main.rs` 做语法解析校验（exit 0 即语法通过）。
- 需要给用户出 exe 时，让用户自己在本机终端执行 `cargo build --release`。

## 新增打包脚本（未提交）
- `pack.ps1`（UTF-8 **带 BOM**，PS 5.1 读中文必须带 BOM）+ `pack.cmd`（任意终端里敲 `pack 1.5.0` 的入口）。
- 流程：校验版本号三段式 → 只改 `Cargo.toml` [package] 段里的 version → `cargo build --release` → 拷 `target\release\iClick-gpui.exe` 到 `dist\iClick-gpui.exe` → `Compress-Archive` 出 `dist\iClick-gpui_v<ver>.zip`。
- 开关：`-NoZip`、`-DryRun`（只验版本号改写，改完立刻还原）、`-Open`；不写版本号 = 用现有版本重打。
- 编译失败/中途异常会自动把 Cargo.toml 还原成原版本号（已用假 cargo 实测）。
- 两个已踩平的坑：① 正则必须把 `[package]` 到 version 之间的内容放进第 1 组，否则 `[package]`、`name` 行会被吃掉（一开始就是这么错的）；② PS 5.1 在 `$ErrorActionPreference='Stop'` 下会把 cargo 的 stderr 当 ErrorRecord 抛异常，调用 cargo 那段要临时改成 `Continue`，成败只看 `$LASTEXITCODE`。
- 验证手段（不用真编译）：假 `cargo.cmd` 放临时目录前置到 PATH，成功路径造个假 exe 验 dist+zip，失败路径验还原。
